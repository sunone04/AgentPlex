# ADR-0007: Docker 作为沙箱与部署的容器基座

- **状态**: 已接受（2026-08-19）

## 背景

spec §3.6 要求执行层沙箱硬隔离（进程无法越界）；§3.5 要求定时任务离线时降级到云端沙箱；§3.4.2 要求标准化部署包（Docker/K8s Helm）。沙箱是安全承诺的根基，属不可逆安全决策。

## 决策

以 **Docker** 作为容器基座，分两条路径：

1. **桌面端沙箱（本地执行）**：检测到 Docker Desktop → 工具调用（Bash/文件操作）在受限容器内执行（卷挂载 workspace 只读/读写白名单、无宿主网络按策略、资源上限）；无 Docker → **降级为受限子进程模式**（路径约束 + 命令黑名单 + 环境变量脱敏），并在 UI 明示当前隔离级别。隔离级别纳入审计日志。
2. **云端沙箱（降级执行）**：服务器侧 Docker 容器池，按任务临时容器，执行完销毁。

部署交付：MVP 用 Docker Compose（PG + Redis + server + console），企业版输出 K8s Helm chart。

## 理由

1. Docker 是 Windows/macOS/Linux 三平台唯一一致的进程级隔离方案，且企业 IT 普遍具备运维能力。
2. 降级路径保证"零 Docker 环境"（部分企业办公机）仍可用，隔离级别显式化而非静默降级。
3. 与部署交付策略（spec §3.4.2）共用同一技术栈，不引入额外容器运行时。

## 后果

- 正向：沙箱与部署统一容器心智；云端沙箱可复用桌面沙箱镜像。
- 风险：Docker Desktop 在 Windows 企业环境可能被禁用——降级模式即为此兜底；容器内工具链（git/node 等）需打进沙箱镜像并统一版本。

## 备选方案

- **Firecracker / gVisor**：隔离更强，但 Windows 桌面不可用、运维门槛高，云端重沙箱可在企业版阶段再评估。
- **纯进程沙箱（codex linux-sandbox / seatbelt 路线）**：作为降级模式的实现参考，不作为默认承诺。
